# Подготовка данных к обучению: Supervised Learning Classification

## 1. Введение

Цель данного документа — детально описать процесс предобработки датасета `Don'tGetKicked` перед подачей его в модели машинного обучения (`LogisticRegression`, `GaussianNB`, `KNN`).

В задачах классификации качество модели напрямую зависит от корректности представления входных признаков. Основные этапы включают:
1. Разделение выборки во времени (Time-Based Split).
2. Очистку данных от нерелевантных колонок.
3. Обработку пропущенных значений (Imputation).
4. Кодирование категориальных признаков (Encoding).
5. Масштабирование числовых признаков (Scaling).

Все операции выполняются таким образом, чтобы исключить **утечку данных (data leakage)** из обучающей выборки в валидационную и тестовую.

## 2. Исходные данные и структура

Датасет содержит информацию об аукционных продажах автомобилей.
*   **Количество строк:** ~73,000.
*   **Количество колонок:** 34.
*   **Целевая переменная (Target):** `IsBadBuy` (бинарная: 0 — хорошая покупка, 1 — «лимон»).
    *   Баланс классов: ~87.7% (0) / ~12.3% (1). Это умеренный дисбаланс, требующий использования метрик AUC/Gini, а не Accuracy.

### Типы признаков

Для целей предобработки признаки разделены на две группы:

#### А. Числовые признаки (Numerical Features)
Признаки, имеющие непрерывное или дискретное числовое значение, где порядок величин имеет смысл.
*   `VehYear`: Год выпуска автомобиля.
*   `VehicleAge`: Возраст автомобиля на момент покупки.
*   `WheelTypeID`: Тип колеса (код).
*   `VehOdo`: Пробег автомобиля.
*   `MMRAcquisitionAuctionAveragePrice`, `MMRAcquisitionAuctionCleanPrice`, `MMRAcquisitionRetailAveragePrice`, `MMRAcquisitonRetailCleanPrice`: Рыночные цены (MMR) на момент приобретения.
*   `MMRCurrentAuctionAveragePrice`, `MMRCurrentAuctionCleanPrice`, `MMRCurrentRetailAveragePrice`, `MMRCurrentRetailCleanPrice`: Текущие рыночные цены (MMR).
*   `VehBCost`: Стоимость покупки автомобиля.
*   `IsOnlineSale`: Флаг онлайн-продажи (0/1).
*   `WarrantyCost`: Стоимость гарантии.

> **Примечание:** `VNZIP1` (почтовый индекс продавца) формально является числом, но семантически это географический идентификатор. Он обрабатывается как **категориальный** признак, так как арифметические операции над индексами бессмысленны.

#### Б. Категориальные признаки (Categorical Features)
Признаки, принимающие конечное множество текстовых значений или кодов.
*   `Auction`: Название аукционного дома.
*   `Make`: Марка автомобиля.
*   `Model`: Модель автомобиля.
*   `Trim`: Комплектация.
*   `SubModel`: Подмодель.
*   `Color`: Цвет кузова.
*   `Transmission`: Тип трансмиссии.
*   `Nationality`: Страна происхождения производителя.
*   `Size`: Класс размера автомобиля.
*   `TopThreeAmericanName`: Категория бренда (топ-3 американских или другие).
*   `VNST`: Штат продавца.
*   `VNZIP1`: Почтовый индекс (как категория региона).

## 3. Стратегия разделения выборки (Split Strategy)

Согласно заданию, необходимо использовать временной сплит по полю `PurchDate`. Это важно, так как данные представляют собой временной ряд, и случайный перемешивание привело бы к оптимистичной оценке качества (модель могла бы видеть будущие события при обучении на прошлом).

### Правила сплита:
1.  Данные сортируются по возрастанию даты `PurchDate`.
2.  Все уникальные даты делятся на три равные части по количеству дней (не строк, чтобы избежать неравномерности потока продаж в разные дни).
    *   **Train:** Первые 1/3 дат.
    *   **Validation:** Средние 1/3 дат.
    *   **Test:** Последние 1/3 дат.
3.  Условие отсутствия перекрытия: `max(PurchDate_Train) < min(PurchDate_Valid)` и `max(PurchDate_Valid) < min(PurchDate_Test)`.

### Реализация в коде:
```python
df['PurchDate'] = pd.to_datetime(df['PurchDate'])
unique_dates = np.sort(pd.unique(df['PurchDate']))

# Индексы границ
split_idx_1 = len(unique_dates) // 3
split_idx_2 = 2 * len(unique_dates) // 3

date_train_end = unique_dates[split_idx_1]
date_valid_end = unique_dates[split_idx_2]

train_mask = df['PurchDate'] <= date_train_end
valid_mask = (df['PurchDate'] > date_train_end) & (df['PurchDate'] <= date_valid_end)
test_mask = df['PurchDate'] > date_valid_end
```

## 4. Очистка данных (Cleaning)

Перед обработкой удаляются колонки, которые не являются признаками или содержат избыточную/шумовую информацию.

### Удаляемые колонки:
1.  **`RefId`**: Уникальный идентификатор записи. Не несет смысловой нагрузки для модели, только увеличивает размерность.
2.  **`PurchDate`**: Используется только для сплита. После разделения выборки исключается из матрицы признаков `X`.
3.  **`PRIMEUNIT`**: Содержит ~95% пропусков. Информация отсутствует для большинства наблюдений, использование такого признака внесет шум.
4.  **`AUCGUART`**: Аналогично `PRIMEUNIT`, ~95% пропусков.
5.  **`IsBadBuy`**: Целевая переменная, выделяется отдельно в вектор `y`.

### Итоговый список признаков для обучения:
*   **Числовые:** `VehYear`, `VehicleAge`, `WheelTypeID`, `VehOdo`, блок `MMR...` (8 колонок), `VehBCost`, `IsOnlineSale`, `WarrantyCost`.
*   **Категориальные:** `Auction`, `Make`, `Model`, `Trim`, `SubModel`, `Color`, `Transmission`, `Nationality`, `Size`, `TopThreeAmericanName`, `VNST`, `VNZIP1`.

## 5. Предобработка (Preprocessing Pipeline)

Используется механизм `sklearn.compose.ColumnTransformer` для применения разных стратегий к разным типам данных. Важно: **Fit** выполняется только на тренировочной выборке (`X_train`), а **Transform** применяется к валидации и тесту.

### 5.1. Работа с пропусками (Missing Values)

#### Числовые признаки
Многие MMR-цены имеют небольшие пропуски (<1%). Для их заполнения используется медиана, так как она устойчива к выбросам (в отличие от среднего значения).

*   **Стратегия:** `SimpleImputer(strategy='median')`
*   **Обоснование:** Распределения цен могут быть скошены. Медиана сохраняет центральную тенденцию лучше, чем среднее, если есть экстремальные выбросы.

#### Категориальные признаки
Пропуски в таких полях, как `Trim`, `Color`, `Transmission`, встречаются редко (<5%). Их можно заполнить специальным маркером "missing" или наиболее частым значением. Однако, создание отдельной категории "Unknown" часто информативнее, так как сам факт пропуска может указывать на специфический источник данных или состояние авто.

*   **Стратегия:** `SimpleImputer(strategy='constant', fill_value='missing')`
*   **Обоснование:** Позволяет модели различать случаи, когда информация известна, и когда она отсутствует. При One-Hot Encoding появится отдельный столбец для 'missing'.

### 5.2. Кодирование категориальных признаков (Encoding)

Для линейных моделей (LR) и KNN необходимо преобразовать текст в числа.

*   **Инструмент:** `OneHotEncoder(handle_unknown='ignore', sparse_output=False)`
*   **Параметр `handle_unknown='ignore'`:** Критически важен. Если в валидационной или тестовой выборке встретится новая категория (например, новый штат или модель авто), которой не было в трейне, энкодер просто вернет нулевые векторы для этой строки вместо ошибки. Это обеспечивает устойчивость пайплайна.
*   **Параметр `sparse_output=False`:** Возвращает плотную матрицу (numpy array), что удобно для дальнейшей работы с `StandardScaler` и моделями sklearn.

> **Альтернатива:** Для признаков с высокой кардинальностью (например, `Model` или `VNZIP1`) One-Hot Encoding может сильно увеличить размерность пространства (curse of dimensionality). В данном проекте мы начинаем с OHE для простоты и интерпретируемости. Если качество упадет из-за разреженности, будет рассмотрено Target Encoding или Frequency Encoding.

### 5.3. Масштабирование числовых признаков (Scaling)

Логистическая регрессия и KNN чувствительны к масштабу признаков.
*   `VehOdo` (пробег) имеет значения порядка десятков тысяч.
*   `IsOnlineSale` принимает значения 0 или 1.
*   Без масштабирования градиентный спуск в LR будет сходиться медленно, а расстояния в KNN будут определяться преимущественно пробегом, игнорируя другие важные факторы.

*   **Инструмент:** `StandardScaler()`
*   **Формула:** $z = \frac{x - \mu}{\sigma}$
*   **Результат:** Каждое числовое特征 имеет среднее 0 и стандартное отклонение 1.

### 5.4. Порядок операций в ColumnTransformer

Важно соблюдать правильный порядок внутри пайплайнов для каждой группы признаков:

1.  **Numeric Pipeline:**
    *   Step 1: Imputation (Median) -> Заполняем NaN.
    *   Step 2: Scaling (StandardScaler) -> Нормализуем заполненные данные.
    *   *Почему так:* Нельзя масштабировать данные с NaN. Сначала чистим, потом нормируем.

2.  **Categorical Pipeline:**
    *   Step 1: Imputation (Constant 'missing') -> Заполняем NaN.
    *   Step 2: Encoding (OneHotEncoder) -> Превращаем текст в бинарные векторы.
    *   *Почему так:* Энкодер должен видеть все возможные значения, включая импутированные.

## 6. Контроль утечки данных (Leakage Control)

Утечка данных происходит, когда информация из будущего (валидация/тест) попадает в процесс обучения. Мы защищаемся от этого следующими мерами:

1.  **Временной сплит:** Обучаем только на прошлых датах.
2.  **Раздельный Fit/Transform:**
    *   `preprocessor.fit_transform(X_train)` — параметры импутеров и скалеров вычисляются ТОЛЬКО на трейне.
    *   `preprocessor.transform(X_valid)` — те же самые параметры применяются к валидации. Новые статистики не пересчитываются.
3.  **Handle Unknown Categories:** Один хот энкодер настроен на игнорирование неизвестных категорий, чтобы не падать при встрече новых значений в тесте, но при этом не использовать статистику теста для обучения.

## 7. Результат предобработки

После применения пайплайна мы получаем три матрицы признаков:
*   `X_train_processed`: Плотная числовая матрица `(n_train_samples, n_features_encoded)`.
*   `X_valid_processed`: Аналогичная матрица для валидации.
*   `X_test_processed`: Аналогичная матрица для теста (используется только в самом конце).

И соответствующие векторы ответов:
*   `y_train`
*   `y_valid`
*   `y_test`

Эти данные готовы к передаче в методы `.fit()` моделей `LogisticRegression`, `GaussianNB` и `KNeighborsClassifier`.

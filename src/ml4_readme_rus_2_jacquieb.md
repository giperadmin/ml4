## Глава I. Преамбула

Ты уже изучил задачи регрессии. Мы можем пытаться предсказывать такие величины, как возраст человека, цены акций, погоду на завтра (температуру) и т. д. Но что, если мы хотим предсказывать **категориальные** признаки: есть ли у пациента определённое заболевание, какие цифры изображены на дорожном знаке? Такие задачи называются **задачами классификации**. Они похожи на задачи регрессии, но имеют свою специфику.

Мы рассмотрим 3 типа моделей классификации: логистическую регрессию (своего рода модификацию линейной регрессии), наивный байесовский классификатор (модель, созданную специально для задач классификации) и KNN (который применим как к задачам регрессии, так и к задачам классификации).


## Глава II. Введение

Задачи классификации похожи на задачи регрессии. В задачах классификации пространство выходов — это множество из **C** неупорядоченных и **взаимоисключающих** меток (классов); мы хотим построить такую функцию *f*:

$$f: X \rightarrow Y, \text{ где } Y \in \lbrace 1, 2, \dots, C \rbrace, X - \text{ обучающая выборка}$$

Когда у нас всего два класса (то есть $$Y \in \lbrace 0, 1 \rbrace$$), задача называется **бинарной классификацией**. В этом уроке мы сосредоточимся на бинарных задачах.

Примеры бинарной классификации из реальной жизни:
* Есть ли у пациента определённое заболевание.
* Является ли транзакция мошеннической.
* Нажмёт ли пользователь на рекламный баннер в мобильном приложении.
* Вырастет или упадёт цена определённой акции в ближайшие несколько секунд (полезно для трейдинга).
* Вернёт ли клиент кредит (вероятность дефолта, PD; полезно в банковской сфере).

С вероятностной точки зрения задачу бинарной классификации можно рассматривать как оценку вероятности того, что данный объект x имеет метку 1:

$$p(y=1|\mathbf{x}, \boldsymbol{\theta}), \mathbf{x} - \text{объект, } \boldsymbol{\theta} - \text{параметры модели}$$

Бинарные задачи — лишь частный случай задач классификации (если ***C*** больше 2, задача называется **многоклассовой**). Подходы к бинарным задачам можно использовать для решения многоклассовых: решаем ***C*** разных бинарных задач по схеме «один против всех» (one-vs-all), то есть обучаем ***C*** моделей, где для **i**-й бинарной задачи целевая переменная равна 1, если y = i, и 0, если y ≠ i. Чтобы сделать предсказание в таком случае, достаточно взять *argmax* из ***C*** полученных оценок:

$$\arg \max_{i \in \lbrace 1, 2, \dots, C \rbrace} p(y=i|\mathbf{x}, \boldsymbol{\theta})$$

Иногда (для решения бизнес-задач) удобнее переформулировать задачи регрессионного типа в бинарные: предсказывать, выше ли доход человека среднего дохода по его стране, или предсказывать направление движения цены акции (как в примере выше). Иногда задачи классификации можно превратить в задачи регрессии, упорядочив метки. В определении выше мы задали множество меток C как неупорядоченное, но иногда удобно решать задачу как классификацию, даже если метки упорядочены.

### Логистическая регрессия

#### Постановка

Логистическая регрессия — это модель следующего вида:

$$p(y=i|\mathbf{x}, \boldsymbol{\theta}) = \sigma (a) = \frac{1}{1 + e^{-a}}, \text{где } a = \mathbf{w}^T \mathbf{x} + b \text{ и } \boldsymbol{\theta} = (\mathbf{w}, b)$$

Функция $$\sigma$$ называется **сигмоидой**. Логистическая регрессия эквивалентна линейной комбинации признаков матрицы ***X*** с добавлением свободного члена (смещения) ***b***. Иногда (при математических выкладках) ***b*** включают в вектор ***w***, добавляя в ***X*** дополнительный столбец из единиц. Чтобы вычислить выход логистической регрессии для конкретного объекта ***x***, нужно умножить каждую компоненту ***x*** на соответствующую компоненту ***w***, прибавить смещение ***b***, а затем «сжать» результат сигмоидой. Можешь построить график сигмоиды и убедиться, что её значения лежат между 0 и 1. «Регрессия» — лишь часть названия алгоритма, к задаче регрессии он отношения не имеет.

Логистическая регрессия — не лучший алгоритм с точки зрения точности (в среднем), но она интерпретируема: любому менеджеру или пользователю легко объяснить, как работает такая модель. Между параметрами и данными есть простая связь.

Как выбрать параметры $$\boldsymbol{\theta} = (\mathbf{w}, b)$$? Есть удобный способ обучения моделей — метод максимального правдоподобия (Maximum Likelihood Estimation, MLE). Мы хотим найти параметры, которые максимизируют вероятность получить данный набор данных ***X*** с ***Y***. Формально это записывается так:

$$p(y|\mathbf{x}, \boldsymbol{\theta}) = \sigma (a) = \frac{1}{1 + e^{-a}}$$

что эквивалентно

$$p(y|\mathbf{x}, \boldsymbol{\theta}) =\text{Ber}\left(y|\sigma(\mathbf{w}^T \mathbf{x} + b)\right)$$

где Ber — [распределение Бернулли](https://ru.wikipedia.org/wiki/Распределение_Бернулли).

Мы берём произведение функций плотности вероятности для всех объектов в наборе данных, а затем логарифмируем его (это корректно, поскольку мы считаем все объекты независимыми). Полученная функция, взятая со знаком минус, называется **отрицательным логарифмом правдоподобия (Negative Log Likelihood, NLL)**. Применение MLE в этом контексте означает минимизацию NLL. Вывод приведён в качестве бонусного материала.

Для поиска параметров, минимизирующих NLL, можно использовать любой градиентный алгоритм оптимизации. Градиент и гессиан для NLL вычисляются легко, так что подойдёт любой метод, использующий градиент и гессиан. Тебе нужно вывести градиент NLL вручную (он понадобится для решения задач по программированию). Если застрянешь — загляни в эту [книгу](https://probml.github.io/pml-book/book1.html). Один из лучших способов оптимизации NLL — **стохастический градиентный спуск (SGD)**, но можно использовать и методы второго порядка, например **метод Ньютона**.

Разные программные реализации предлагают разные методы. Для обучения на тысячах или миллионах объектов SGD подходит лучше, чем метод Ньютона (исследуй и выясни почему). Стохастический градиентный спуск — мощный метод, который применяется не только для обучения логистической регрессии: это базовый метод оптимизации параметров моделей **глубокого обучения**.

Для моделей логистической регрессии обычно используют те же методы предобработки, что и для линейной регрессии: масштабирование, one-hot-кодирование категориальных признаков и т. д. Для пропусков (NaN) можно использовать заполнение средним/модой и добавить дополнительный признак — флаг того, было ли значение в данном признаке пропущено.

#### Ограничения и сильные стороны

Логистическая регрессия — интерпретируемый алгоритм, что делает её привлекательной для отраслей со строгим регулированием (например, банковской) или там, где нужна 100% объяснимость (некоторые научные области). Простая форма модели гарантирует объяснимость, но ведёт к менее точным моделям. Грубо говоря, ты жертвуешь мощностью модели ради её простоты. У логистической регрессии всего

*число-числовых-признаков + число-всех-категорий-в-категориальных-признаках + 1*

параметров, поэтому этот алгоритм менее склонен к переобучению (чем более сложные алгоритмы).

Но как улучшить базовую логистическую модель? Логистическая регрессия — линейная модель, единственная нелинейная часть которой — сигмоидная функция активации. Поэтому подогнать логистическую регрессию под нелинейную зависимость между ***X*** и ***Y*** будет непросто. Геометрически модель логистической регрессии — это гиперплоскость в пространстве признаков: она способна разделять классы лишь в относительно простых случаях.

Однако мы можем преобразовать вход ***X*** с помощью нелинейных преобразований (формально — применить к ***X*** некоторую нелинейную функцию ***φ***). Иногда этот приём позволяет решать сложные задачи. Посмотри на рисунок ниже:

![pic1](misc/images/transform_figure.png)

На рисунке мы превращаем квадратичную разделяющую границу в линейную, вычислив квадратичные признаки:
$`x_1 \rightarrow x_1^2`$ и $`x_2 \rightarrow x_2^2`$

> Источник: [Kevin Murphy, Probabilistic Machine Learning: An Introduction](https://probml.github.io/pml-book/book1.html)

Распространённые варианты этого приёма:
* Логарифмы признаков (особенно признаков с тяжёлыми хвостами).
* Полиномиальные признаки.
* Отношения признаков: признак №1 / признак №2.
* **Sin(x)** или **Cos(x)** для улавливания периодических компонент.
* Признаки в духе выходов деревьев: сравнения вида «больше ли признак №1 числа **k**».

У добавления признаков есть недостатки: в среднем большее число признаков может вести к большему переобучению.

Сложные признаки делают итоговую модель менее интерпретируемой. Тем не менее иногда можно найти баланс между объяснимостью и точностью. Классический пример — кредитный скоринг:

![pic2](misc/images/credit_score_cards.png)

Непрерывные признаки (например, возраст) **разбиваются на интервалы (биннинг)** — это нелинейная операция, но итоговую модель легко объяснить кому угодно: достаточно посмотреть на признаки и соответствующие веса («баллы» на рисунке).

### Наивный Байес

#### Постановка

Существует ещё один простой подход к задачам классификации — **наивный байесовский алгоритм** (NB). В его основе лежит следующее допущение: все признаки условно независимы при заданной метке класса (отсюда и слово «наивный»). Это допущение слишком сильное, чтобы выполняться в реальных сценариях, но NB-классификаторы часто дают хорошие результаты даже при его нарушении.

Основная идея метода — вычислить апостериорную вероятность по формуле Байеса:

$$\text{апостериорная} = \frac{\text{априорная} \cdot \text{правдоподобие}}{\text{обоснованность (evidence)}}$$

$$p(y=c|\mathbf{x}) = \frac{p(y=c) p(\mathbf{x}|y=c)}{p(\mathbf{x})} = \frac{p(y=c) p(\mathbf{x}|y=c)}{\sum_{c'} p(y=c') p(\mathbf{x}|y=c')}$$

Таким образом, наша цель — максимизация апостериорной вероятности (MAP-оценка). Если присмотреться к знаменателю, станет понятно, что он постоянен, поскольку значения признаков $$x_i$$ для набора данных фиксированы. Более того, если допущение NB выполняется, можно выразить вероятность получить вектор признаков $$\mathbf{x}$$ при условии, что метка _y_ этого вектора равна классу _c_:

$$p(\mathbf{x} | y=c) =\prod_{d=1}^D p \left( x_d | y=c \right)$$

где $$x_d$$ — признак _d_ объекта $$\mathbf{x}$$.

Объединяя всё вместе, получаем, что задача максимизации апостериорной вероятности эквивалентна:

$$p(y=c) p(\mathbf{x}|y=c) \rightarrow \max$$

Чтобы использовать эту формулу для обучения классификатора, нужно:

1. задать вид распределения для априорных вероятностей;
2. задать вид распределений признаков;
3. оценить и то и другое.

Априорное распределение в классификации моделируется распределением Бернулли или мультиномиальным распределением. Хорошая оценка вероятности класса в этом случае — доля этого класса в наборе данных. Что касается распределений признаков:

- Для бинарных признаков используем [распределение Бернулли](https://ru.wikipedia.org/wiki/Распределение_Бернулли).
- Для непрерывных признаков можно использовать нормальное распределение или сделать их бинарными и остаться с Бернулли.
- Для категориальных признаков подходит категориальное (или мультиномиальное) [распределение](https://en.wikipedia.org/wiki/Categorical_distribution).

Опять же, в реальных задачах распределения признаков могут отличаться от Бернулли/мультинулли/нормального, но, как и в случае с допущением NB, иногда всё равно удаётся обучить точный NB-классификатор.

Для вычисления оптимальных параметров NB-модели (снова) можно использовать метод максимального правдоподобия (MLE). Можно показать (см. раздел 9.3.2 [книги](https://probml.github.io/pml-book/book1.html)), что обучение NB-классификаторов сводится к вычислениям с простыми подсчётами признаков (в случае бинарных или категориальных признаков) или квадратов отклонений от среднего (в случае непрерывных признаков). Никакой сложной процедуры оптимизации — только простые и быстрые вычисления на обучающих данных.

#### Ограничения и сильные стороны

Очевидно, допущение NB — главное ограничение: в большинстве реальных сценариев качество NB-алгоритма невысокое. Его основные преимущества — простота обучения и естественная обработка пропущенных значений.

### KNN

#### Постановка

У моделей LR и NB есть соответствующие **параметры**. Мы используем данные, чтобы оценить оптимальные параметры, а после обучения можем выбросить весь набор данных. У непараметрических моделей нет фиксированного набора параметров: эффективное число параметров модели может расти вместе с размером набора данных. Пример такой модели — KNN.

Идея проста: чтобы классифицировать новый объект ***x***, находим ***K*** ближайших к ***x*** объектов в обучающей выборке (используя какую-либо метрику, например расстояние L2 или L1), затем усредняем метки ***K*** найденных соседей и получаем предсказание.

![pic4](misc/images/knn.png)

> Источник: [Kevin Murphy, Probabilistic Machine Learning: An Introduction](https://probml.github.io/pml-book/book1.html)

Оптимизации нет: мы находим ближайших соседей и храним данные в памяти.

#### Ограничения и сильные стороны

Главная сложность KNN — выбор метрики расстояния. L1/L2 подходят, когда данные однородные и непрерывные. В остальных случаях расстояния между объектами не так информативны. Ещё одна проблема — проклятие размерности: при большом числе признаков объекты оказываются слишком далеко друг от друга. KNN требует много памяти: для инференса нужно хранить все обучающие данные.

Тем не менее есть разные подходы к решению (или хотя бы частичному решению) всех этих проблем: способы ускорения, поиска более подходящих метрик расстояния, хранения обучающих данных и запросов к ним. Сегодня KNN используется как строительный блок для других алгоритмов ML (например, рекомендательных систем).

### SVM

Ещё одна модель для задач классификации — [метод опорных векторов](https://ru.wikipedia.org/wiki/Метод_опорных_векторов) (Support Vector Machines, SVM). SVM может быть линейным или нелинейным (иначе говоря, с нелинейным ядром). В линейном случае SVM пытается разделить классы гиперплоскостью, но строит эту гиперплоскость несколько иначе (с использованием *зазоров*, margins). Нелинейный случай предполагает преобразование пространства признаков с помощью *ядер* перед построением гиперплоскости, чтобы классы стали линейно разделимыми.

Обучение SVM — это оптимизация с ограничениями.

Линейный SVM плохо справляется с нелинейными зависимостями, а нелинейный SVM можно рассматривать как частный случай нейронных сетей, поэтому подробно описывать SVM здесь мы не будем. В [этой статье](https://en.wikipedia.org/wiki/Support_vector_machine) есть хорошее базовое описание SVM.

#### Метрики

Наиболее распространённая функция потерь в задачах классификации — logloss. Однако как метрика качества для бизнес-приложений эта функция — не лучший выбор.

Есть несколько часто используемых метрик (мы по-прежнему минимизируем logloss при обучении алгоритмов, где это уместно, но решения о модели принимаем по другим метрикам):
1. Precision/Recall (точность/полнота);
2. F1-мера;
3. Fbeta-мера;
4. AUC PR;
5. AUC ROC.

AUC-метрики считаются для бинарных задач, а Precision/Recall/F1/Fbeta можно обобщить на многоклассовый случай. Для простоты остановимся на бинарных задачах.

##### Precision/Recall

Precision и Recall — метрики для «жёстких» меток: не вероятностей, а предсказанных классов. Жёсткие метки получаются из оценённых вероятностей с помощью порога:

$$\mathbb{I}(p(y=1|x) \> \text{threshold})$$

где $$\mathbb{I}$$ — индикаторная функция (единица или ноль в зависимости от утверждения: единица, если оно истинно, иначе ноль).

Жёсткие метки позволяют построить **матрицу ошибок** (confusion matrix). Определение и подробности о матрице ошибок описаны в этом [источнике](https://ru.wikipedia.org/wiki/Матрица_ошибок) — изучи его, прежде чем читать следующий абзац.

![pic5](misc/images/precision.png)

> Источник: https://medium.com/analytics-vidhya/what-is-a-confusion-matrix-d1c0f8feda5

Precision и Recall определяются как

```math
Precision = {tp \over {tp + fp}} \\
Recall = {tp \over {tp + fn}}
```

Из формул вытекают интерпретации:
* Precision — *какая доля предсказанных единиц действительно является единицами*.
* Recall — *какую долю настоящих единиц предсказала наша модель*.

Для оценки качества модели используют сочетания Precision и Recall: можно максимизировать Recall при заданном минимально допустимом уровне Precision или наоборот.

В одних задачах Recall важнее Precision:
* Медицинские случаи, где дополнительное обследование безопасно и дёшево (хочется выявить как можно больше заболеваний, а ошибки FP приводят к ограниченным затратам/ущербу);
* Выявление мошенничества;
* Рекомендация релевантного контента (онлайн-курсы, видео и т. д.).

В других случаях Precision предпочтительнее Recall:
* Медицина: углублённое обследование или лечение слишком вредно или дорого;
* Рекомендации для VIP-клиентов (не хочется беспокоить лучших клиентов нерелевантными рекомендациями);
* Системы безопасности в аэропортах.

##### F1-мера

Precision и Recall можно объединить с помощью подходящего усреднения. Среднее гармоническое Precision и Recall называется F1-мерой.

$`F = 2 \cdot {precision \cdot recall \over {precision + recall}}`$

F1 обеспечивает баланс между Precision и Recall.

##### Fbeta-мера

Если мы хотим уделить больше внимания Recall или Precision, используем Fbeta-меру — обобщение F1:

$`F_{\beta} = (1 + \beta^2) \cdot {precision \cdot recall \over {\beta^2 \cdot precision + recall}}`$

*При каком значении параметра Recall получает больший вес, чем Precision?*

##### AUC PR

При оптимизации Fbeta-меры всё равно нужно подбирать оптимальный порог. Average Precision (AP) можно рассматривать как способ агрегировать Precision и Recall по всем возможным порогам. В [документации sklearn](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html) есть хороший обзор AP.

##### AUC ROC

В [этом источнике](https://alexanderdyakonov.wordpress.com/2017/07/28/auc-roc-%D0%BF%D0%BB%D0%BE%D1%89%D0%B0%D0%B4%D1%8C-%D0%BF%D0%BE%D0%B4-%D0%BA%D1%80%D0%B8%D0%B2%D0%BE%D0%B9-%D0%BE%D1%88%D0%B8%D0%B1%D0%BE%D0%BA/)
дано подробное объяснение AUC ROC. AUC ROC можно интерпретировать как вероятность следующего события:

*[предсказанная вероятность для случайного объекта класса 0 < предсказанная вероятность для случайного объекта класса 1]*.

Обрати внимание: базовое значение (для случайного шума) метрики AUC ROC равно 0,5, а не 0!

**Коэффициент Джини** можно рассматривать как «ненаправленный» AUC ROC; он вычисляется по формуле: *|2\*ROC AUC − 1|*
